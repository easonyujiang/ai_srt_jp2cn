Module 1 · 深入

M1 FFmpeg 命令与进度机制

core FFmpeg 命令 ffmpeg -i input.mp4 \ -vn # 丢弃视频流 -acodec pcm_s16le # 16-bit 有符号 PCM -ar 16000 # 16kHz 采样率（下游统一要求） -ac 1 # 单声道 -y # 覆盖已有文件 output_16k.wav
📊

实时进度提取

用正则表达式 time=(\d+:\d+:\d+\.\d+) 从 stderr 中解析当前处理时间，除以总 duration 得到百分比。

⏱️

总时长获取

通过 ffprobe 在编码开始前获取视频总时长：
ffprobe -v error -show_entries format=duration。

🎯

三种进度模式

终端动画（anim）→ 可解析行（line）→ 自动检测（auto）。通过 --progress-style 参数控制，适配 GUI 和 CLI 场景。

🛡️

错误处理

检查 FFmpeg 是否安装 → 检查返回码 → 输出文件是否存在 → 集合 stderr 内容报错，确保失败时有足够调试信息。

Module 2 · 深入

M2 显存自适应与分片策略

Demucs 模型在消费级 GPU 上处理长音频容易 OOM。M2 通过 GPU 显存检测自动决定分片策略。

🔍

GPU 显存检测

调用 torch.cuda.get_device_properties(0).total_mem 获取总显存。备选方案：nvidia-smi（命令行查询）。

✂️

低显存分片模式

显存 < 12GB 且音频长度 > 8分钟时，按 CHUNK_SECONDS=480 秒切片。每段独立推理后 empty_cache() 释放显存。

🚀

全速模式

显存 ≥ 12GB 直接全量处理，模型一次加载不释放。避免分片拼接开销和边界伪影。

🔄

降采样输出

Demucs 44100Hz 输出 → 用 torch.cat 拼接各片段 → Resample 降回 16000Hz → 写入 16-bit PCM WAV。

Module 3 · 核心流程

M3 四阶段处理详解

M3 的核心函数 transcribe_and_align() 内部分为四个严格顺序的阶段。

1

语音转写 (ASR)

加载 faster-whisper large-v2 的 CTranslate2 格式模型（int8 量化）。调用 model.transcribe(audio, batch_size=16) 输出段落级时间戳和文本。

2

词级对齐 (Alignment)

加载 Wav2Vec2 (xlsr-53-japanese) 日语专精模型。使用 whisperx.align() 将每个词与音频波形强制对齐，分配独立时间戳。

3

说话人分离 (Diarization)

使用 pyannote 的 segmentation-3.0 + speaker-diarization-3.1 pipeline，配合 ECAPA-TDNN / WeSpeaker embedding 模型进行多说话人聚类。

4

说话人分配 (Assign)

调用 whisperx.assign_word_speakers() 将 diarization 结果分配到对齐后的每个词上。最终每个 word 和 segment 都带 speaker 标签。

模型推理全部在 GPU 上完成。低显存模式下，每个阶段结束后显式调用 del model; torch.cuda.empty_cache() 释放资源。

Module 3 · 工程适配

M3 七层兼容性补丁

由于 WhisperX / faster-whisper / PyTorch 生态版本迭代频繁，M3 在 import 阶段自动应用 7 个 monkey-patch。

🔧

faster-whisper API 适配

TranscriptionOptions 旧版缺少 max_new_tokens/clip_timestamps 参数，patch 后自动补默认值。

🔧

PyTorch 2.6+ 安全加载

lightning_fabric._load 和 torch.load 全局添加 weights_only=False，兼容旧模型 checkpoint。

🔧

SpeechBrain 循环导入防护

LazyModule.ensure_module 增加 _pending 集合检测，防止递归导入时无限重试导致挂死。

🔧

离线模型优先

huggingface_hub.hf_hub_download 强制 local_files_only=True，失败时在 snapshots/ 中手动搜索 candidate 文件。

🔧

VAD 降级兜底

pyannote VAD 模型未缓存时自动降级为全 1 输出的虚拟 VAD（_DummyVAD），允许 pipeline 继续运行。

🔧

Windows DLL 支持

自动 os.add_dll_directory(libs/) 使 cuDNN 8.9 的 7 个 DLL 可被 Python 加载器发现。

🔧

本地路径识别

补丁 faster_whisper.utils.download_model，使 SDK 识别本地 snapshot 目录而不是把它当成 repo_id 发起网络请求。

🔧

Align 模型本地注入

替换 DEFAULT_ALIGN_MODELS_HF[ja] 为本地缓存路径，绕过在线下载。完成后恢复原始值。

Module 3 · 性能工程

M3 低显存串行加载策略

三个 AI 模型（ASR + 对齐 + 说话人）如果同时驻留 GPU 需要 ~16GB 显存。 M3 通过显存检测自动切换串行加载模式，让 8GB 消费级显卡也能完成整套流程。

💾 串行化流程（显存 < 12GB 时启动）

加载 ASR 模型 → 转写 → del model; torch.cuda.empty_cache() → 加载对齐模型 → 对齐 → del model_a; torch.cuda.empty_cache() → 加载说话人模型 → 分离 + 分配 → del diarize_model; torch.cuda.empty_cache()

📏

显存阈值

VRAM_LOW_THRESHOLD_GB = 12。低于此值启动串行模式，否则全驻留。RTX 3060/4060 (6-8GB) 自动走串行。

🔬

计算精度

GPU 默认 float16，CPU 默认 int8。可通过 --compute-type 参数覆盖。int8 量化牺牲少量精度换取更低显存。

Module 4 · 工程实现

M4 切片调用与容错机制

✂️

切片 API 调用

当 segments 超过 max_segments_per_chunk（默认 50）时，按固定大小切片分批调用 DeepSeek。每片处理完成后自动修正 original_index 偏移（+= chunk_start）。

🔄

指数退避重试

API 调用最多重试 3 次。第 1 次等 2s、第 2 次等 4s、第 3 次等 8s。所有超时和瞬时错误均触发重试。

🛡️

JSON 解析容错

1. 移除 markdown 代码块标记。2. json.loads 标准解析。3. 失败时用正则 \[.*\] 提取数组并重试。4. 仍失败抛出含错误上下文异常。

🔑

API 密钥预检

启动时校验 DEEPSEEK_API_KEY 是否合法（检查非占位值 + 含 sk- 前缀），提前明确报错而非等待 API 超时。

模型参数

Module 5 · 核心算法

M5 align_and_rebuild 详解

1

检测模式

检查 cleaned_data 所有片段是否都含 original_index。全有 → 索引映射模式；否则 → 顺序匹配退化。

2

索引分组

用 defaultdict(list) 按 original_index 分组。每组内的所有片段对应 M3 中的一个原始时间段。

3

比例分配

计算组内各片段 text_len / total_text_len 的比例。片段起始 = start + cum_ratio*duration，长度 = ratio*duration。

4

过滤与输出

过滤短于 0.5s 片段 → 替换说话人名 → 生成 ASS/SRT 文本 → 写入文件。

rebuild_subtitle.py · 时间比例分配核心 for orig_idx, grp in groups.items(): raw_seg = raw_data[orig_idx] start, end = raw_seg["start"], raw_seg["end"] duration = end - start total_text_len = sum(len(s["text"]) for s in grp) cum_ratio = 0 for seg in grp: ratio = len(seg["text"]) / total_text_len seg_start = start + cum_ratio * duration seg_end = seg_start + ratio * duration seg_start = max(start, min(seg_start, end)) # 防溢出 subtitle_entries.append({...}) cum_ratio += ratio

这种按文本长度比例分配时间的方法，确保 M4 拆分后的短句不会错位或越界，始终在原段时间区间内。

当条目数超过 max_lines_per_chunk（默认 20）时，自动分片独立调用 API。每片独立 prompt + 独立响应解析，避免 LLM 长文本注意力分散导致漏翻或合并。

🛡️

四层 JSON 容错

1. 移除 markdown 代码块。2. json.loads 解析。3. 失败时正则 \[.*\] 提取。4. 仍失败抛出错误，包含前 200 字符原文供排查。

🔢

严格条目数校验

翻译结果数量必须与原文数量严格一致。不一致时抛出详细错误，包含前 300 字符原始响应，便于排查 LLM 合并遗漏问题。
